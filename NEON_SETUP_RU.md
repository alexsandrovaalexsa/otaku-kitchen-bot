# 🍡 Otaku Kitchen — автоматическое добавление рецептов (Neon + Render)

Текущий бот уже запущен: https://t.me/otakukitchen_recipes_bot. Эта версия сохраняет новые рецепты из **публичного** канала https://t.me/otakukitchen в постоянную базу Neon PostgreSQL. Для каждого нового рецепта больше не надо обновлять GitHub.

## Перед началом

- **Не публикуйте токен от BotFather и строку подключения Neon** в Telegram, в чате, на GitHub или на скриншотах. Храните их только в Render → Environment.
- Сохраняйте текущий архив бота для возможности отката.
- Ничего не надо удалять из существующего GitHub-репозитория.
- Render остаётся бесплатным, но может засыпать через 15 минут без запросов. Бесплатный Neon тоже имеет квоты; это не гарантия 100% доступности.

## 1. Создайте базу Neon бесплатно

1. Откройте https://console.neon.tech/ и войдите / зарегистрируйтесь.
2. Нажмите **Create project** (или **New project**). Название, например, `otaku-kitchen`.
3. Выберите тариф **Free**, регион по возможности близкий к вашему сервису Render (если Render размещён в Oregon, необязательно выбирать Frankfurt).
4. После создания проекта найдите **Connect** / **Connection Details** и выберите `Postgres` / строку подключения. При доступности опции `Pooled connection` её можно включить.
5. Скопируйте **полную** строку вида:
   `postgresql://USER:PASSWORD@HOST.neon.tech/neondb?sslmode=require`
   Здесь `USER`, `PASSWORD` и `HOST` — только пример. Не вписывайте их буквально. Не показывайте эту строку никому.

## 2. Добавьте DATABASE_URL на Render

1. Откройте https://dashboard.render.com/ → сервис `otaku-kitchen-bot` → **Environment**.
2. Нажмите **Add Environment Variable**.
3. `KEY`: `DATABASE_URL`
4. `VALUE`: вставьте полную строку из Neon (без кавычек, без пробелов).
5. Сохраните изменения. Перезапуск старого кода после добавления переменной допустим: он пока использует JSON, а не Neon.
6. Существующий `BOT_TOKEN` не меняйте.

## 3. Сначала обновите Build Command на Render

1. Откройте `otaku-kitchen-bot` → **Settings** → **Build & Deploy**.
2. Найдите **Build Command** и установите:

   `pip install "psycopg[binary]>=3.2,<4"`

3. Сохраните. Новый Build Command будет работать **и со старой, и с новой версией кода**, поэтому его безопасно менять до обновления GitHub.
4. **Start Command** оставьте `python webhook.py` и **Compute** оставьте `Free`.

## 4. Один раз обновите файлы на GitHub

1. Распакуйте архив `otaku_kitchen_NEON_auto.zip`.
2. Откройте GitHub → существующий репозиторий `otaku-kitchen-bot`.
3. Нажмите **Add file → Upload files**. Перетащите **содержимое** распакованной папки (файлы `bot.py`, `webhook.py`, `db_store.py`, `requirements.txt` и остальные), не ZIP целиком и не вложенную папку.
4. Если GitHub предложит заменить существующие файлы, подтвердите; **старый репозиторий удалять не нужно**. Если веб-интерфейс не позволяет замену, воспользуйтесь GitHub Desktop или пришлите скриншот — не создавайте файлы с суффиксом `(1)`.
5. Нажмите **Commit changes**. При включённом **Auto-Deploy: On Commit** Render начнёт развёртывание сам.

## 5. Проверьте Render

Откройте сервис в Render → **Deploys/Logs**. Ожидаются записи:

- `Deploy succeeded | Live`
- `Listening on port 10000, recipes loaded: 284` (или больше)
- `Webhook configured: https://otaku-kitchen-bot.onrender.com/telegram`

Таблицы базы данных и первоначальный импорт **284 записей** создаются автоматически при первом успешном запуске; **не нужно вручную вставлять SQL**. При следующем перезапуске бот загружает их из Neon, не заменяя новыми старыми версиями из JSON.

Если `ModuleNotFoundError: psycopg`, значит Build Command ещё старый. Если `DATABASE_URL not set` — не сохранена переменная в Render Environment. Если `Database startup retry...` — проверьте URL Neon, но **не публикуйте его в логах или скриншотах**.

## 6. Добавьте бота администратором Telegram-канала

1. Откройте канал `@otakukitchen` → **Управление каналом** → **Администраторы** → **Добавить администратора**.
2. Добавьте `@otakukitchen_recipes_bot`.
3. Боту нужно получать новые **channel_post** обновления. Не давайте разрешения на удаление сообщений, управление администраторами или другие необязательные права. Если Telegram требует выбрать хотя бы одно право, дайте минимально необходимое право, которое допускает его интерфейс.
4. Теперь новые посты с хэштегами `#завтрак`, `#обед`, `#ужин`, `#десерт`, `#напитки` и **не менее двумя распознанными ингредиентами** становятся видимы в каталоге. Посты с нераспознанным составом получают флаг проверки и не показываются в выдаче.
5. Публикации должны содержать **текст или подпись к фото/видео**. Бот не распознаёт продукты из одних только картинок.

## 7. Проверка на новом посте

Создайте **тестовую** публикацию в канале (её увидят подписчики) со следующим текстом или используйте следующий реальный рецепт:

```
🧪 Тестовый рецепт Otaku Kitchen
Ингредиенты:
🥚 Яйца — 2 шт.
🥛 Молоко — 100 мл
🌾 Мука — 120 г

Приготовление:
Смешайте продукты и приготовьте блюдо.

#завтрак@otakukitchen
#легко@otakukitchen
```

В Render в логах появится `Recipe stored: <номер поста>`. У бота откройте **Завтраки** — новый рецепт должен появиться первым, а кнопка откроет соответствующую публикацию в Telegram.

После проверки можете **отредактировать тестовый пост**: поменяйте название и убедитесь, что оно обновилось в боте. Для удаления теста из каталога сначала отредактируйте пост и уберите хэштег `#завтрак` (бот удалит его из поиска), затем при желании удалите пост из Telegram. **Просто удаление поста в канале не создаёт события удаления в Bot API**, поэтому без предварительной правки он может остаться в каталоге.

## Важно знать

- Первоначальные 284 публикации импортируются **однократно**. Не придётся вручную переносить старые рецепты.
- Новые рецепты и их правки сохраняются в Neon, включая URL конкретного поста.
- Публикации без категорий и новости канала не добавляются как рецепты.
- Если сервер долго спал, новое сообщение Telegram может прийти с задержкой; Render не гарантирует ответ сразу. Если Telegram не доставит сообщение после нескольких неудач, его можно снова отредактировать, чтобы бот получил обновление.
- Удалённый пост без предварительного снятия категории может остаться в каталоге: Telegram Bot API не сообщает об удалении постов канала.
- Изменение **кода** бота всё ещё требует одного коммита в GitHub; публикация **рецептов** — нет.
- Количество имеющихся ингредиентов бот сравнивает по названиям, не по массе/объёму.
